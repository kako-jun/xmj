## 1. 構造役 — 🔴 8 種が未実装 (常に不成立)

`scoring.rs` の以下の detector が **ハードコードで `false` / `None` を返すスタブ**のまま。`agari.rs` に和了形分解エンジン (`enumerate_decompositions_with_wait`) があるにもかかわらず未接続。

| 役 | 関数 | 現状 | file:line |
|---|---|---|---|
| 一盃口 Iipeikou | `check_iipeikou` | `false` | scoring.rs:664-668 |
| 二盃口 Ryanpeikou | `check_ryanpeikou` | `false` | scoring.rs:671-675 |
| 三色同順 Sanshoku | `check_sanshoku_doujun` | `None` | scoring.rs:678-682 |
| 一気通貫 Ittsu | `check_ittsu` | `false` | scoring.rs:685-689 |
| 混全帯么 Chanta | `check_chanta` | `false` | scoring.rs:692-696 |
| 純全帯么 Junchan | `check_junchan` | `false` | scoring.rs:699-703 |
| 三色同刻 Sanshoku-doukou | `check_sanshoku_doukou` | `false` | scoring.rs:770-774 |
| 小三元 Shousangen | `check_shousangen` | `false` | scoring.rs:777-781 |

**影響**: これらの役を含む手はその飜が一切加算されない。三色同順 (門前2飜) や一気通貫を狙う手が「リーチのみ1飜」に化ける等、点数が体感で半分以下になるケースがある。小三元(2飜+役牌)が付かないのは特に痛い。

**修正方針**: `agari.rs` の `Decomposition`(雀頭+4面子) を使えば全て判定可能。`enumerate_decompositions_with_wait` は副露なし14枚専用なので、副露あり手 (Chanta/Sanshoku/Ittsu/Shousangen は鳴いても成立) には副露面子を含めた分解が要る。`ScoringEngine` に「副露 melds を Mentsu に変換 → 手牌分解と結合 → 各役を分解上で判定」する共通パスを足すのが筋。テスト基盤 (`tests/yaku_situational.rs`) があるので回帰防止しながら入れられる。

## 2. 三暗刻 Sanankou — 🔴 手牌内暗刻を数えない

`check_sanankou` (scoring.rs:757-767) は **副露 (closed kan 等) の暗刻だけ** をカウントし、`ankou_count >= 3` で判定している。手牌に普通に組まれた暗刻 (例: 門前で 222m 555p 888s の3暗刻) は副露ではないので **0 カウント → 三暗刻が付かない**。最も一般的な「門前3暗刻」が成立しない。

**影響**: 四暗刻 (`agari::is_suuankou`) は分解エンジンで正しく判定されているのに、三暗刻だけ取りこぼす。

**修正方針**: 分解 (`Decomposition`) 上で Koutsu の数を数え、ロン和了牌が組み込まれた刻子は明刻扱いに格下げ (四暗刻と同じ明暗ロジック)。

## 3. 符計算 calculate_fu — 🔴 スタブ

`calculate_fu` (scoring.rs:1186-1198) は:

```rust
let mut fu = 20;            // 基本符
if is_tsumo { fu += 2; }    // ツモ符
((fu + 9) / 10) * 10        // 切り上げ
```

待ち符・面子符・雀頭符・門前ロン符・平和/七対子の特殊符を **一切計算していない**。結果、符は常に 20 (ロン) or 30 (ツモ) になる。

**未計算の符 (標準)**:
- 門前ロン +10
- 明刻 (中張 2 / 么九 4) / 暗刻 (中張 4 / 么九 8) / 明槓 (8/16) / 暗槓 (16/32)
- 役牌雀頭 +2 (連風牌 +2 or +4)
- 嵌張/辺張/単騎待ち +2
- 平和ツモ 20 固定 / 平和ロン 30 固定
- 七対子 25 固定
- 喰い平和形 (鳴き20符) はロンで22→30切り上げ等

**影響**: 満貫未満の手の点数がほぼ全て誤り。例: 30符4飜=7700 のはずが、符が30固定でも `30 * 2^6 = 1920 → base 1920` で total 子ロン 7680。逆に本来40符の手が30符扱いで過小。リーチ・タンヤオ・ピンフ等の頻出手の点数が体感とズレる。

**修正方針**: 分解 (`Decomposition`) + 待ち形 (`MachiKind`) + メルド情報 + ctx(場風/自風) から標準符計算を実装。平和・七対子の固定符を分岐。

## 4. 満貫頭打ちなし — 🟠 High

`calculate_base_points` (scoring.rs:1200-1209):

```rust
1..=4 => fu * (1 << (han + 2)),   // ← 2000 で頭打ちしない
5 => 2000, 6..=7 => 3000, ...
```

4飜以下で `fu * 2^(han+2)` が 2000 を超えても満貫に丸めない。標準では base が 2000 以上なら満貫扱い (例: 4飜40符 = 40×64 = 2560 → 満貫2000、3飜70符 = 2240 → 満貫2000)。

**現状での実害は限定的**: 符が常に 20〜30 に固定されている (#3) ため `4飜30符 = 1920 < 2000` で頭打ちに到達しないケースが多い。だが **符計算 (#3) を直すと顕在化する** ので同時に修正すべき。切り上げ満貫 (kiriage) を入れるかは toggle 検討。

## 5. 平和 Pinfu — 🟠 雀頭の役牌判定が三元牌のみ

`agari::is_pinfu_shape` (agari.rs:297-316) は雀頭が役牌かのチェックを **三元牌 (白發中) のみ** で行い、場風・自風の風牌雀頭を除外していない (関数が場風/自風を知らないため)。

**影響**: 例えば東場・東家で「東東」を雀頭にした全順子手が平和成立と誤判定される (本来は役牌雀頭で平和不成立)。`check_pinfu` 側も `winning_tile` だけ渡して ctx を渡していない。

**修正方針**: `check_pinfu` / `is_pinfu_shape` に `round_wind` / `seat_wind` を渡し、雀頭がそれらの風牌なら不成立に。
